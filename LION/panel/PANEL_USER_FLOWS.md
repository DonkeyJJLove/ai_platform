# Panel user flows

## Observe mission

Mission Control → mission list/detail → phase/worker/model/receipt projections → currentness labels. Observation does not authorize mutation.

## Submit canonical model chat

Conversation → route selection (LOCAL/SAAS/DUAL) → durable request/correlation identity → provider leg(s) → response reconciliation → transcript delivery.

`SAAS_QUEUED` and `DUAL_WAITING` are transport/execution states, not completed cognition.

## Bind or detach mission context

Conversation successor binding updates conversation context identity. It does not by itself grant mission execution authority.

## Protocol plane

Protocol transcript is separate from Model Chat transcript and keeps protocol participant/causation semantics.

## Consequential operator action

Select control → show exact target/currentness → request authority/admission → execute bounded action → read back actual state → reconcile → update UI.

Any failed or unknown link remains visible as FAILED/UNKNOWN; the UI must not synthesize success.
